# ROOT Operating Doctrine & Technology Standard v3

**Status:** Canonical  
**Effective:** 2026-09-16  
**Version ID:** `ROOT-TECH-V3-2026-09-16`

## Operating Doctrine
ROOT is the default optimization target for work, learning, tools, purchases, content, networking, projects, and other discretionary activities.

Whenever reasonably possible, convert time, attention, assets, knowledge, relationships, and activity into ROOT revenue, customer acquisition, market intelligence, product insight, brand equity, operational leverage, capability, cost reduction, or strategic advantage.

Ambition is deliberately high. Execution must remain durable, disciplined, evidence-based, lawful, and sustainable.

## Non-Negotiable Boundaries
- No harm to people.
- No illegal activity.
- No privacy, security, consent, contractual, regulatory, or platform-policy violations.
- No fraud, coercion, deception, harassment, exploitation, or unsafe shortcuts.
- Protect health, family responsibilities, and basic human needs as long-term strategic assets.

## Enforcement Rules
1. ROOT Technology v3 is the mandatory default stack for new ROOT architecture, coding, deployment, QA, documentation, security, analytics, integrations, and operations.
2. Appwrite is the primary application/backend platform.
3. GitHub Pages is for documentation/project sites, not the primary application runtime.
4. DIRT is embedded inside ROOT as the Revenue Intelligence/data-intelligence capability and follows this standard unless a temporary legacy exception is required.
5. Azure, Codespaces, and Termius are on **HOLD** and are not selected for new ROOT work unless explicitly reactivated.
6. Blockchair is **FUTURE** scope and is not a current production dependency unless explicitly approved.
7. Avoid duplicate platforms and tool sprawl. Reuse an existing ROOT Technology v3 capability before introducing another service.
8. Alternatives require a documented technical/business reason, a required dependency, or explicit approval.

## Decision Test
> Before committing time, money, compute, or attention: **How does this create revenue, leverage, intelligence, distribution, capability, resilience, or strategic advantage for ROOT?**

## Source-of-Truth Rule
Mirror this standard into operational systems using each platform's native form—documents, presentations, design files, repositories, project documents, and structured records. When versions conflict, the newest explicitly approved ROOT standard controls.
